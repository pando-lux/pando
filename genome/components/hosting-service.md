# Hosting Service (Phase 32 + Phase 62 URL Injection)

## What It Does

Deploys project sites to AWS S3 so users can access them via the web. Public projects are served directly via the S3 website endpoint. Private and shared projects are served via pre-signed URLs with a 1-hour TTL, blocking direct access with a 403.

## Gateway URL Injection (Phase 62)

When `GATEWAY_PUBLIC_URL` or `GATEWAY_URL` is set, `deployAgentWorkspace()` injects a `<script>` tag into every HTML file before uploading to S3:
```html
<script>window.PANDO_GATEWAY_URL="https://gateway-one-mu.vercel.app";window.PANDO_PROJECT_ID="my-project";</script>
```
This enables S3-hosted apps to call the gateway's Resource Proxy for database access (cross-origin). Builders write `fetch(window.PANDO_GATEWAY_URL + '/api/resource-proxy/db', ...)` — no hardcoded URLs. See `genome/flows/app-hosting.md` for the full 3-tier hosting architecture.

## How It Works

- **S3 bucket:** `pando-deployments` in `us-east-1`. Bucket policy allows public read only on the `public/*` prefix.
- **Public projects:** Files uploaded to `public/<projectId>/`. Served directly via `http://pando-deployments.s3-website-us-east-1.amazonaws.com/public/<projectId>/`.
- **Private/shared projects:** Files uploaded to `private/<projectId>/`. Direct access returns 403. Accessible only via pre-signed URLs (1-hour TTL) generated by `getDeploymentInfo()`.
- **File upload format:** API accepts base64-encoded files in JSON body. Each file has a `path` (relative) and `content` (base64 string).
- **Removal:** `remove()` lists all objects under the project prefix and issues a batch delete.
- **Probe:** `probe()` does a lightweight HEAD request to check if a deployment exists without generating URLs.
- **Dependencies:** `@aws-sdk/client-s3` for S3 operations, `@aws-sdk/s3-request-presigner` for pre-signed URL generation.

## API Routes (in api-server.ts)

| Method | Path | Auth | Description |
|---|---|---|---|
| POST | /projects/:id/hosting | Owner/admin token | Deploy files (base64 JSON body) |
| GET | /projects/:id/hosting | Optional user token | Get deployment info + URL |
| DELETE | /projects/:id/hosting | Owner/admin token | Remove all deployed files |

## Types

- **`DeploymentInfo`** (in `packages/shared/src/types.ts`): `{ deployed: boolean, projectId: string, projectType: string, url: string, fileCount: number, totalSize: number, deployedAt: string }`

## Clean URL Delivery (Phase 52)

When `GATEWAY_PUBLIC_URL` or `GATEWAY_URL` is set, deployment URLs use the gateway format:
`https://gateway/apps/<projectId>/index.html` instead of raw S3 URLs.

The gateway serves deployed content at `/apps/*` by proxying to S3 (`app/apps/[...path]/route.ts`). This means users get clean, shareable URLs. Raw S3 URLs are only used as fallback when no gateway URL is configured.

## Gotchas

- AWS credentials must be available in the environment (`~/.aws/credentials` or env vars) for S3 operations. Nodes without credentials cannot host.
- The S3 bucket policy only allows public read on the `public/*` prefix. Any change to the bucket policy could expose private deployments.
- Pre-signed URLs expire after 1 hour. Clients must call `GET /projects/:id/hosting` again to get a fresh URL.
- File paths in the upload body are relative to the project root. The service prepends `public/<projectId>/` or `private/<projectId>/` automatically.
- Set `GATEWAY_PUBLIC_URL` to get clean deployment URLs (e.g., `https://gateway-one-mu.vercel.app`).

## Agent-Driven Deployment

Deployment is **agent-driven, not infrastructure-driven**. The manager agent decides when to deploy and calls `POST /agents/:id/deploy` (which calls `AgentManager.deployAgentWorkspace()`). There is no automatic deployment triggered by infrastructure after agent events.

The flow:
1. Manager agent finishes building a project
2. Manager decides deployment is appropriate (taught via manager template "## Deployment" section)
3. Manager calls `POST /agents/:id/deploy` with its own agent ID
4. AgentManager reads the agent's workspace files, calls `HostingService.deploy()`
5. Structured JSON response returned to the agent (URL, file count, size)
6. Manager tells the user the deployment URL
